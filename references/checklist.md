# 体检清单

**先归类**：按功能定类别（见 `references/taxonomy.md`），类型不同检查重点不同。

## A 结构

**先确认场景**：本地自用 / 发布分发——两者对 README、LICENSE、NOTICE 的要求不同（发布必须有 LICENSE 与 README；本地可有可无）。判定前先问是哪种，避免拿发布标准查本地技能，或反过来。

按 Agent Skills 规范，技能目录只应有这些：

```
技能名/
├── SKILL.md          ← 必需
├── scripts/          ← 可选：可执行脚本
├── references/       ← 可选：按需加载的文档
└── assets/           ← 可选：模板、图片、字体
```

| 检查 | 判定 |
|---|---|
| `SKILL.md` 在根下，没套一层文件夹 | 硬伤 |
| 只有 `scripts/`、`references/`、`assets/` 三个目录 | 提示（**官方 spec 允许任意额外文件/目录**，但非标准目录部分平台可能不识别） |
| 参考文件只一层深（不出现 `references/a/b/c`） | 警告 |
| 根目录的 `README.md`、`CHANGELOG.md` | 提示（本地技能不需要；**发布到 GitHub 时 README 是必需的**，不算缺陷） |
| `LICENSE` / `NOTICE.md` 允许存在 | 提示（法律文件，不占上下文；发布时建议有） |
| 根目录无 `AGENTS.md` | 警告（仓库级配置，不属于技能） |
| 无 `__pycache__`、`.DS_Store`、`.git`、`.pyc` | 警告（构建垃圾） |
| 无孤儿文件（`references/`、`scripts/`、`assets/` 里每个文件都能从 SKILL.md 出发被引用到） | 警告 |
| 引用的路径都带扩展名 | 建议 |
| 超过 100 行的参考文件有目录 | 建议 |
| 【仅 WorkBuddy】有 `agent_created: true` | 警告（否则平台无法管理） |
| 【仅 WorkBuddy】改过市场技能后已标 `userModified: true` | 警告（否则更新会覆盖） |

### Token / 长度预算

| 对象 | 建议 | 警告 | 报错 |
|---|---|---|---|
| `SKILL.md` 正文 | ≤ 500 行 / ≤ 5,000 token | 超过即警告 | — |
| 单个 reference 文件 | — | > 10,000 token | > 25,000 token |
| 所有 reference 合计 | — | > 25,000 token | > 50,000 token |
| 非标准文件合计 | — | > 25,000 token | > 100,000 token |

> 粗估：中文约 1.5 字/token，英文约 4 字符/token。

### 孤儿文件怎么查

从 SKILL.md 出发，看每个文件路径有没有在正文（含代码块、行内代码）里被提到；被提到的文件再往下链。引用不到的就是孤儿。

### Markdown 完整性

- **未闭合代码块**（``` 或 ~~~）→ 硬伤。会让模型把后面全部内容当成代码
- 断掉的内链 → 硬伤（指向不存在的文件）

## B frontmatter 与触发

| 检查 | 判定 |
|---|---|
| 有 `name` 和 `description` | 硬伤 |
| `name` 只含小写字母、数字、连字符，≤64 字符，**不能以连字符开头或结尾** | 硬伤 |
| `name` 与文件夹同名 | 硬伤 |
| 未知字段 | 警告（平台可能不认） |
| `compatibility`（若有）≤500 字符 | 警告 |
| Codex 场景是否有 `agents/openai.yaml`（若约定要加） | 提示（生成前须问用户） |
| `allowed-tools`（若有）是空格分隔的工具名 | 提示（官方标注 Experimental） |
| 触发方式符合意图：要自动→不加 `disable-model-invocation`；要手动→加上（**Codex 不认该字段，改用 `agents/openai.yaml` 的 `policy.allow_implicit_invocation: false`**） | 硬伤 |

## C description

| 检查 | 判定 |
|---|---|
| ≤ 1024 字符（跨平台硬线） | 硬伤 |
| 含「做什么」+「什么时候触发」 | 硬伤 |
| **关键词堆砌**：5 个以上引号短语，且正文词数少于引号数 | 警告 |
| **关键词堆砌**：8 段以上逗号分隔的短片段 | 警告 |
| 过宽（什么都能触发） | 警告（会误触发） |
| 过窄（只有精确词才触发） | 警告（会永不触发） |

### 压缩 description 的顺序

1. 删重复的同义触发词
2. 删「边界说明」「注意事项」（属于正文）
3. 删举例堆叠（留最典型的 3–5 个）
4. 合并句式

## D 安全

**出现任何一条 → 停下报给用户，不装不跑：**

- 向未知地址发网络请求（域名既不是官方也不是用户指定）
- 上传本地数据到外部服务器
- 索要凭证 / token / API key
- 读 `~/.ssh`、`~/.aws`、`~/.config` 且无正当理由
- 读浏览器 cookie / 会话
- 对任意输入用 `eval()` / `exec()`
- base64 解码后执行
- 删除或修改工作区外文件
- 未声明就安装软件包
- 访问 IP 而不是域名
- 代码被压缩 / 编码 / 混淆

### 「危险」与「正常」（避免误杀）

| 看起来危险 | 其实正常 |
|---|---|
| 文档里出现 `curl` / `wget` | 教程教用户怎么做，不是技能自己要跑 |
| 出现 `password` / `API_KEY` | `.env.example` 里的占位符，是正确做法 |
| 出现 `rm -rf` | 排错文档里教用户重置 |
| 出现 `base64` | API 文档里的编码示例 |
| 出现绝对路径 | 在示例输出里，不在指令里 |

**判断标准：它是「指令」还是「示例」？会不会被自动执行？**

## E 冲突与依赖

| 检查 | 说明 |
|---|---|
| 技能名与已装技能重名 | 重名 → 哪份生效不确定，必须解决 |
| description 与已装技能抢同一场景 | 写明谁优先，或合并 |
| 依赖的外部命令是否存在 | `node`/`python`/`ffmpeg`/专用 CLI，逐个 `--version` 验证 |
| 依赖的环境变量是否已配置 | 没配就写「需配置 X」 |
| 是否依赖平台专有能力 | MCP 工具、内置浏览器、特定 CLI → 换平台失效 |
