# 技能功能分类（不是所有技能都为代码而生）

> 类型不同，**检查重点不同**。给技能体检时先归类，再按对应列重点查。

## 一、十一类技能

| 类别 | 典型技能 | 检查重点 | 常见失败模式 |
|---|---|---|---|
| **① 办公文档** | docx、xlsx、pptx、pdf、office-* | 文件格式兼容、能否打开、有没有破坏原文件 | 生成的文件打不开；公式不重算；字体缺失 |
| **② 写作与内容** | doc-coauthoring、humanizer、写作质量、去 AI 味 | 输出风格是否稳定、有没有 AI 腔、术语一致性 | 每次都写得不一样；越改越啰嗦 |
| **③ 研究与文献** | research、论文写作、文献综述 | **引用是否真实可核**、有没有编造出处 | 幻觉引用；来源不可达 |
| **④ 视频与多媒体** | remotion、字幕、转录、剪辑 | 依赖是否齐（ffmpeg / node / GPU）、渲染时长、版权 | 装了 CLI 却没装；模型要 GPU 跑不动 |
| **⑤ 设计与视觉** | canvas-design、theme-factory、品牌规范 | 产出格式（PNG/PDF）、字体授权、可编辑性 | 只能看不能改；字体版权 |
| **⑥ 游戏开发** | Unity、Unreal、Godot、自研引擎 | **引擎版本绑定**、API 是否过期、能否在目标版本跑 | 文档对应旧版本；引擎 API 改了 |
| **⑦ 翻译与本地化** | 翻译、术语表、双语对齐 | 术语一致性、保留原文标识符、编码 | 译名不统一；代码/变量被误译 |
| **⑧ 数据与分析** | 表格处理、SQL、统计 | 数据准确性、边界值、可复现 | 静默丢行；口径不一致 |
| **⑨ 知识与笔记** | Obsidian、笔记整理、知识图谱 | 文件组织、链接不断、可检索 | 链接腐烂；重复条目 |
| **⑩ 工程与代码** | tdd、code-review、调试、重构 | 可执行、可测试、版本匹配 | 示例代码跑不通 |
| **⑪ 系统与元技能** | 造技能、技能体检、插件开发 | 规范符合度、跨平台、自我一致 | 标准打架；自相矛盾 |

## 二、按类型调整检查力度

| 类型 | 结构检查 | 安全检查 | 效果测试 | 特别提示 |
|---|---|---|---|---|
| ①⑦⑨（文档/翻译/笔记） | 重点 | 中（会读写本地文件） | **必须看真实产物** | 检查编码与字体 |
| ②⑤（写作/设计） | 中 | 低 | 只能定性看，难量化 | 别用死板断言，会误杀 |
| ③⑧（研究/数据） | 中 | 中 | **必须核事实** | 查引用真实性、样本口径 |
| ④⑥⑩（视频/游戏/工程） | 中 | 中高（会跑命令） | 需要真实环境跑一遍 | 查依赖版本 |
| ⑪（元技能） | **最严** | 高（会影响其他技能） | 自测 + 交叉测 | 查是否与其他技能冲突 |

## 三、归类时问三个问题

1. **它产出的是什么**？文字 / 文件 / 代码 / 视频 / 只是一段建议？
2. **它要动什么**？只读资料 / 读写本地文件 / 跑命令 / 联网？
3. **失败怎么发现**？肉眼能看出 / 要跑才知道 / 要核事实才知道？

答案决定：用哪套检查重点、要不要写测试、能不能量化。

## 四、混合类型怎么处理

一个技能常常横跨两类（例：读书笔记整理 = ③研究 + ⑨笔记）。

做法：**按「最终交付物」归类**，另一类作为次要检查项。

- 交付物是笔记 → 主类 ⑨，附带查 ③ 的引用真实性
- 交付物是论文 → 主类 ③，附带查 ⑨ 的组织性

## 五、和「能力提升型 / 偏好编码型」的关系

分类是**横轴**（做什么），类型是**纵轴**（为什么需要它）：

| | 能力提升型 | 偏好编码型 |
|---|---|---|
| 代码类 | 补模型不会的实现 | 团队/项目的代码规范 |
| 写作类 | 补特定文体能力 | 固定的写作流程与口吻 |
| 研究类 | 补检索与核证能力 | 固定的文献管理流程 |

**判断意义**：能力提升型要定期测「还需不需要」；偏好编码型要测「流程忠不忠实」。
